# Kubernetes Lables

当Pod非常多的时候，通过 Labels 分类能更方便管理。Labels 可以任意自定义。

Label虽然好，但只用Label的话，那Label会非常多，有时候会有重叠，而且每次查询之类的动作都带一堆Label非常不方便。Kubernetes提供了Namespace来做资源组织和划分，使用多Namespace可以将包含很多组件的系统分成不同的组。Namespace也可以用来做多租户划分，这样多个团队可以共用一个集群，使用的资源用Namespace划分开。

Kubernetes 标签（Labels）是附加到集群资源上的键值对，主要用于标识、组织和选择资源子集。它们是实现多维度资源分组管理的关键，例如根据环境（env=dev）、版本（version=stable）或服务层级（tier=backend）对 Pod、Service 等资源进行分类。通过使用标签，用户可以灵活地进行资源分配、调度、配置和部署管理。

资源选择与查询：标签允许用户使用标签选择器来查询和选择特定的对象集合。例如，可以通过 app=myapp 来选择所有与 myapp 相关的 Pod。


```shell
kubectl get ns  # 查看所有 namespace
```
[官方标签说明](https://kubernetes.io/zh-cn/docs/concepts/overview/working-with-objects/labels/)
[官方常用标签](https://kubernetes.io/zh-cn/docs/concepts/overview/working-with-objects/common-labels/)

```yaml
labels:
  app: h5|web|backend
  env: dev|production   # 环境
  release: stable|canary
  tier: frontend|backend|cache                # 服务层级
```
