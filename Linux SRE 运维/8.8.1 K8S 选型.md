# Kubernetes 选型




* K3S 适用于物联网IoT、边缘计算等资源受限环境，内存只需512M、程序不足100MB
* K3S 也适用单机服务器场景，Kubeadm 需要2-3G启动内存，而K3S只需要0.5-1GB。因此单机服务器更适合 K3S
    * 中小型集群



k3s = SQLite(代替ETCD) + containerd + Flannel CNI + Traefik Ingress
docker = containerd + buildah（构建镜像）



* kubernetes: 容器编排引擎，自动部署、管理容器
* pod: k8s 最小可部署单元，封装1个或多个容器
* docker: 容器引擎，k8s 使用 containerd 代替
* containerd: docker作者开发的一个行业标准容器运行时
* buildah: 容器工具集，RedHat 团队开发，更适用于构建优化镜像，配合 containerd 管理容器
* podman: 容器工具集，命令跟docker几乎一致，包含构建镜像 + 管理容器


你需要在每台机器上安装以下的软件包：
* kubeadm：用来初始化集群的指令。
* kubelet：在集群中的每个节点上用来启动 Pod 和容器等。
* kubectl：用来与集群通信的命令行工具。只有Master Node才能执行 kubectl


* ctr: containerd 原生客户端工具，不支持Pod管理
* crictl: k8s 工具，支持Pod管理


默认端口：
* 2379 ETCD
* 6443 API server
* 8080 API server
* 10250 kubelet
* 30000-32767 Node 端口

**Requirements**:
* 控制平面（master node）CPU 核心数 >= 2；工作节点至少1个CPU核心
* 每台机器 内存 >= 2GB
* 集群所有机器能互相连接（公网和内外都可以）
* 节点间不能有重复主机名、MAC地址或product_uuid
* 关闭交换分区(Swap) 和 selinux



## Affinity 和 Taint

节点亲和性（Affinity）是 Pod 的一种属性，它使 Pod 被吸引到一类特定的节点。 污点（Taint） 则相反，它使节点能够排斥一类特定的 Pod。

容忍度（Toleration） 是应用于 Pod 上的。容忍度允许调度器调度带有对应污点的 Pod。 容忍度允许调度但并不保证调度：作为其功能的一部分， 调度器也会评估其他参数。

污点和容忍度（Toleration）相互配合，可以用来避免 Pod 被分配到不合适的节点上。 每个节点上都可以应用一个或多个污点，这表示对于那些不能容忍这些污点的 Pod， 是不会被该节点接受的。

```shell
# 给k8s-master节点增加一个污点(taint)
kubectl taint nodes k3s-master node-role.kubernetes.io/control-plane:NoSchedule
# 给k8s-master节点移除一个污点
kubectl taint nodes k3s-master node-role.kubernetes.io/control-plane:NoSchedule-
```

## CNI插件

CNI插件（Container Network Interface，也称Pod网络插件）要解决三个问题：
1. Pod-to-Pod 通信： 确保所有 Pod（无论在哪台节点上）可以通过 IP 地址直接通信。
2. Pod-to-Service 通信： 实现 Kubernetes Service 的负载均衡（ClusterIP, NodePort）。
3. 网络策略（NetworkPolicy）： 实现 Pod 之间的网络隔离和访问控制（类似于防火墙规则）。

CNI插件：
* 基于 Overlay 网络
    * Flannel：安装简单，适用中小型
    * Weave Net：安装简单，适用中小型
* 基于三层路由（BGP）
    * Calico：性能最好、功能最强大、最enterprise-ready的插件，是生产环境的首选之一
* 基于 eBPF：利用 Linux 内核的革命性技术 eBPF，在内核层面直接处理网络数据包，代替传统的 iptables 实现 Service 负载均衡和网络策略
    * Cilium：Linux内核>=4.19，性能极佳（尤其在大规模 Service 时），延迟更低，资源消耗更少。对性能、安全性和可观测性有极致要求的现代化云原生环境，特别是 Service Mesh 和微服务架构。

| 特性	    | Flannel	          | Calico	           | **Cilium**	  | Weave Net       |
|--------|-------------------|-------------------|--------------|-----------------|
| 核心模式   | 	Overlay (VXLAN)	 | 路由 (BGP) / IPIP   | 	eBPF	       | Overlay (VXLAN) | 
| 性能	    | 中等	高 (BGP模式下)	    | 极高 (尤其Service多时)	 | 中等           |
| 网络策略   | 	需 Canal 组件	      | 非常强大              | 	最强大 (支持L7)  | 	基础             | 
| 安装复杂度	 | 非常简单	             | 中等	               | 中等/复杂        | 	简单             | 
| 适用规模   | 	中小型	             | 大型/企业级	           | 大型/高性能	      | 中小型             | 
| 特色	    | 简单、稳定             | 	功能全、生产首选	        | 基于 eBPF、未来趋势 | 	开箱即用、内置加密      |
